# Verification status and how to close the gap

`ae-a8n` is **not** verified against a real After Effects. This document says
exactly what that means, and what to run on a machine that has one.

## The boundary

```text
Confirmed
──────────────────────────────
  TypeScript public API
  protocol codec (envelope, version rejection)
  host dispatch (every method in the table)
  result protocol (request/result files, publish-by-rename)
  driver loop (poll, backoff, timeout, error surfacing)
  ES3 JSON codec, differential against Node's
  trace (ordering, redaction, file/live-view agreement)
  test runner, assertion, snapshot, artifact, report, timeout
                    │
                    ▼  the *same* host/a8n-host.js, evaluated in node:vm,
                       with native JSON removed, File.rename taking a name,
                       and a nested $.evalFile kept off the global object —
                       each as observed on AE 26.5x89

Not confirmed
──────────────────────────────
  OS launcher            AfterFX.exe -r / osascript DoScript: spawn, exit,
                         error propagation
  AE ExtendScript runtime   the engine itself, and its File/Folder semantics
  AE filesystem behaviour  flush, encoding, path escaping, when a written
                         file is actually visible to the reading process
  AE process lifecycle     behaviour when AE is already running vs. not;
                         modal/startup dialogs blocking a script
  Real project            a real .aep, not a placeholder
  Real plugin             match-name and parameter discovery, and what
                         happens when a plugin fails to load
  Real frame render       CompItem.saveFrameToPng: completion, resolution
  AE failure behaviour    crash, hang, and whether either is distinguishable
                         from a timeout
  Cross-platform paths    temp directories and path representation on
                         Windows and macOS
  Diagnostics             whether the disabled "Allow Scripts to Write Files
                         and Access Network" preference produces a usable
                         diagnosis or only a timeout
```

Everything above the line is exercised by the same host script that a real
After Effects session would run. Everything below it is a property of After
Effects, the OS, or a plugin — none of which exist in this environment.

The lower half is **not** a short list. Each line is a separate thing that only
a real host can answer, and several of them have not been thought about at all
yet. Treat the count as a measure of remaining work, not a formality.

against the previous code:

- discovery: the bundle is `<root>/Adobe After Effects N/Adobe After Effects N.app`
  and its executable is `After Effects`;
- the bare application name `"Adobe After Effects"` does not resolve (-2741);
- `File.rename` takes a name, not a path;
- `app.build` is undefined; `app.buildNumber` exists;
- AE has no `JSON`; a nested `$.evalFile` keeps its `var`s off the global object;

Open, not fixed here:

- **Third-party CEP extensions can block AE.** A script that runs long enough
  for AE to pump events (`$.sleep`, a render wait) lets an installed panel

  to load its host bundle, and raised `alert()` — a modal that is often off
  screen, which no script can dismiss. One ae-test repeat stalled at `app.quit`
  with an alert-sized modal window seen around quit; the cause of that one
  instance is not proven.
- **ae-test teardown hides a stuck session.** `TestFixture.teardown` swallows
  `close()` errors, so a test whose session failed to quit is reported as
  passed and the next test launches into the stuck AE.
- ~~`close()` quits an AE it did not start~~ — fixed after `6de80c5`; see
  [sessions.md](sessions.md).

## Closing the gap

On a machine with After Effects installed:

### Prerequisites

1. **Preferences → General → *Allow Scripts to Write Files and Access Network*.**
   Without it the host cannot read the request file or write the result. This
   is the single most likely cause of "it hangs and then times out".
2. A `.aep` with a composition and at least one layer, and the match name of a
   plugin that is actually installed.

### Run the sequence directly

Write this JSX. It must not use `JSON`: AE's ExtendScript has no `JSON`
object (`typeof JSON === "undefined"` on AE 26.5x89), which is why the host
ships its own codec. The build is `app.buildNumber`; `app.build` is undefined.

```js
(function () {
  // Next to this file. (`Folder.temp` is not the shell's temp directory: on
  // macOS it is $TMPDIR/TemporaryItems.)
  var out = new File(new File($.fileName).parent.fsName + "/ae-probe-result.txt");
  out.encoding = "UTF-8";
  out.lineFeed = "Unix";
  out.open("w");
  out.write("version=" + app.version + "\n");
  out.write("buildNumber=" + app.buildNumber + "\n");
  out.close();
})();
```

Run it:

- Windows: `AfterFX.exe -r path\to\probe.jsx`
- macOS: `osascript -e 'tell application "Adobe After Effects 2026" to DoScriptFile "/path/to/probe.jsx"'`
  — name the installed release; the bare `"Adobe After Effects"` does not
  resolve to AE and osascript fails to compile the line (-2741).

If the result file appears with a version in it, the transport's premise holds on
this machine. If it does not, nothing above `ae-a8n` is worth debugging yet.

### Unattended means no dialogs

A script error that escapes into AE becomes a modal alert, and AE then answers
nothing until a person clicks it away — under `DoScriptFile` the AppleEvent
times out after 120 s. The generated entry script therefore catches everything
the host throws, a syntax error included, and publishes it as a failure
envelope. Two dialogs remain outside its reach, because they come from AE
itself before any script runs:

- **Crash recovery**, shown on the launch after AE was killed or crashed. Quit
  AE through `app.quit` / AppleScript `quit`, never by signal, so the next run
  does not start behind it.
- **"The scripting plugin is not installed"**, shown when a script arrives
  while AE is still held at startup (observed only behind the crash-recovery
  dialog).

Neither can be dismissed through accessibility on macOS; AE draws them itself.

### Then, in order

Each step is a question that only a real host can answer. Stop at the first failure.

1. **Does `app.version` come back through the bridge?** Run the probe above by
   hand first, then `AfterEffects.launch()` from Node. This exercises process
   invocation, the request file, the bootstrap, the host script, and the result
   channel together.
2. **Does a real project open?** `app.open(new File(path))`. The fake accepts any
   path; the real one checks the format.
3. **Does a real plugin apply?** `layer.property("ADBE Effect Parade").addProperty(matchName)`.
   This is where the match-name-first, display-name-second lookup earns its keep
   or does not.
4. **Does a parameter read back what was written?** A plugin that silently
   coerces or clamps the value will show up here.
5. **Does a rendered frame land where the host says, at the size it says?**
   The host renders with `CompItem.saveFrameToPng`, waits on the result it
   returns (the file is written after the call returns), forces full
   resolution for the frame, and reports the size from the PNG header.

### What to record

For each step, record: pass or fail, the After Effects version, the OS, and the
plugin match name. Add the row to the table above when it is proven — an
unverified step that gets reported as verified is worse than an unverified step
that is honestly labelled.
