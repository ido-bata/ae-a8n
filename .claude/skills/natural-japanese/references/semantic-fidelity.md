# Semantic fidelity for Japanese rewriting

既存文の推敲では、読みやすさや自然さを改善しても、元の意味を変えてはいけない。表現上の改善より fidelity を優先する。

この reference は [nanaism/yomiyasu](https://github.com/nanaism/yomiyasu) の意味保持・文末・前後比較の考え方を、`natural-japanese` の pipeline に合わせて再構成したもの。source provenance は [../UPSTREAM.md](../UPSTREAM.md) を参照する。

## 1. 書き直す前に固定する4軸

既存文を直す前に、少なくとも次の4点を把握する。

1. **主張** — 何を事実・判断・提案として述べているか。
2. **比重** — 何を重く扱い、何を補足・例外・対比として軽く扱っているか。
3. **certainty** — 断定、推量、可能性、条件付き判断のどの強さか。
4. **communicative function** — 説明、評価、依頼、助言、予定、報告、感想など、文が何をしているか。

書き直した後も4軸が同じであることを確かめる。自然な言い換えでも、これらが動いたなら semantic drift として扱う。

### よくある drift

- 「重要だ」という評価を「目的とする」という目標へ変える
- 「AではなくB」を「Aに加えてB」へ変え、対比の重みを消す
- 「〜かもしれない」を「〜である」へ強める
- 完了済みの変更を「〜します」と将来予定に変える
- 現在の仕様を「今回追加した」と履歴へ変える
- 原文では不明な主体・原因・数値・条件を補って確定する

## 2. 情報を増やさない

推敲のために新しい説明を足してよいのは、原文または提供済み文脈から確定できる場合だけ。

特に次を推測で補わない。

- 主体
- 原因
- 条件
- 数値
- 時点
- 感情・意図
- 比較対象
- 導入・変更・維持といった履歴

referent が曖昧でも、推測で一意化しない。意味を保って暫定表現を残せるなら残し、本文を確定できない場合だけ確認事項として分離する。

## 3. 文末・立場・時制を保つ

日本語では文末が、主体・立場・時制・文の働きを強く示す。

- 説明は説明のまま保つ
- 読み手への依頼は依頼として保つ
- ルールや手順は、単なる提案に弱めない
- 現在の仕様・方針と、将来予定を混同しない
- 実施済みの変更を未来形に戻さない
- 敬体 / 常体の統一と、文の働きの変更を混同しない

語尾の多様化それ自体を目的にしない。同じ文末が続いても、その文の働きに合っているなら残す。

## 4. 比喩・擬人化は意味幅を保って直す

AI的な比喩や擬人化は、具体的な動作へ言い換えられる場合だけ直す。

例:

- 「アクセシビリティが静かに壊れる」→ 何が失われるのかを原文・文脈から特定できる場合だけ具体化する
- 「共通側に倒す」→ 判断先が確定している場合だけ、その判断を平易に書く
- 「効く」「溶かす」「刺さる」→ 効果・時間・対象などを勝手に狭めず、元の意味幅を保つ

非生物主語そのものは禁止しない。システム・API・ツールの客観的動作を述べる主語は自然なら残す。

## 5. 前置き・対比を機械的に削らない

前置きや「〜ではなく」は AI 的な定型になりやすいが、削除すると主張の比重が変わる場合がある。

削除前に確認する。

- その前置きは単なる予告か、それとも評価・前提・制約か
- 対比は誤解訂正に必要か
- 比較から方針へ移る接続を担っていないか
- 削除後も重要度・対立関係・条件が同じか

表層パターンにヒットしたことだけを削除理由にしない。

## 6. deterministic diff を使う

既存文をリライトした場合、可能なら前後比較を実行する。`SKILL_DIR` は、この Skill の `SKILL.md` が置かれたディレクトリの絶対パスとして解決する。

```bash
python "$SKILL_DIR/scripts/fidelity_diff.py" <original> <rewrite> --json
```

この tool は意味変更を判定しない。次のような「意味が動きやすい変更候補」を deterministic に列挙する。

- 明示的な否定表現の増減（文ごとの見直し候補）
- 依頼 / 義務 / 評価 / 推量 / 条件などの marker 数の変化
- 元文にない語
- 消えた語
- 文末の種類の変化
- 箇条書き・段落・文数などの構造変化
- 書き直し後の接続・指示語など、関係を再確認すべき箇所

finding ごとに、4軸と原文を見て次のどちらかへ仕分ける。

- **修正する** — 意味・比重・certainty・function のいずれかが動いた
- **残す** — 表現は変わったが意味は保持されている

tool の出力を自動修正命令として扱わない。

## 7. pre/post fidelity pass

既存文のリライトでは、通常の lint / readability review に加えて次を行う。

### Before

- 主張を1〜数文で要約する
- 重要度・対比・例外を確認する
- certainty を確認する
- 各段落の function と時制を確認する

### After

- deterministic diff の finding を確認する
- 4軸を元文と照合する
- 新しく足した情報に根拠があるか確認する
- 文末・時制・立場が変わっていないか確認する
- 構造を変えた場合、情報の対応関係が失われていないか確認する

自然さの改善と fidelity が衝突した場合は、原文の意味を残す。
